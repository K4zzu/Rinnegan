# Prompt para el agente de backend — Hito 7: Capa de IA (OpenAI)

> Continúa en el MISMO repo `rinnegan-api`. Copia el bloque y pásaselo al agente. Es el último hito de la v1.

---

Continúas `rinnegan-api`. Hitos 1–6 hechos (domain/ip, username, email, phone, name, image). El orquestador ya acumula el **envelope normalizado** (`findings/sources/errors`) y el evento `ai_report` ya está definido en `events.py` pero sin emitirse. **Este es el Hito 7: la capa de IA.** Al cerrar CADA escaneo (de cualquier categoría), un analista LLM lee el envelope, correlaciona y genera un reporte que se emite como `ai_report` justo antes de `done`.

## Objetivo

`app/ai/analyst.py` con una función `async def analyze(envelope) -> str` que, dado el envelope de un escaneo, produce un reporte en **markdown** vía **OpenAI**. El orquestador lo invoca como paso final y emite el resultado como evento `ai_report`. Aplica a TODAS las categorías.

## Dónde engancha (sin romper el contrato)

- El orquestador, **después** de que todos los providers terminan y **antes** de emitir `done`:
  1. Emite `progress` `{provider:"ai", status:"running"}` (para que el frontend muestre "analizando…").
  2. Llama a `analyst.analyze(envelope)`.
  3. Emite `ai_report` `{format:"markdown", text:"<reporte>"}` (UN solo evento con el texto completo — bufferea la respuesta del LLM del lado servidor; no emitas múltiples `ai_report`).
  4. Emite `done` como siempre.
- NO cambies el formato de los eventos ni del envelope. El `ai_report` ya existe en `events.py`.

## Credencial y config (auto-desactivable)

- `OPENAI_API_KEY` — requerida. Si falta → emite `source_error` (`"ai: sin credencial OPENAI_API_KEY"`), **omite** `ai_report`, y sigue a `done` normal. No crashees.
- `OPENAI_MODEL` — default `gpt-4o-mini` (barato/rápido).
- `AI_ENABLED` — default `true`. Si `false`, se salta la IA por completo (sin `ai_report`, sin error).
- Usa el SDK oficial `openai` (cliente async). El "slot" debe quedar aislado en `analyst.py` para poder cambiar de proveedor sin tocar el orquestador.

## Qué produce el analista (un solo prompt estructurado)

Reporte markdown con estas secciones (omite las que no apliquen a la categoría):
1. **Resumen** — qué se encontró, en 2–4 frases claras.
2. **Correlación de identidad** — agrupa hallazgos que apuntan a la misma persona/entidad (mismo handle en varios sitios, email↔usuario, coincidencias de dominio). Señala el nivel de certeza.
3. **Señales / riesgo** — exposición notable (email en brechas, perfiles sensibles, GPS en foto, etc.).
4. **Pivots sugeridos** — próximos pasos concretos ("este usuario también usa X, corre `osint email <...>`").

El prompt del sistema debe instruir: eres un analista OSINT; los datos son **best-effort y sin verificar**; distingue confianza alta vs media; no inventes datos que no estén en el envelope; sé conciso; responde en español.

## Guardas (costo / robustez)

- **Presupuesto de entrada:** limita los findings que mandas al modelo (ej. máx ~80 findings o un tope de caracteres); si hay más, trunca e indícalo en el prompt ("… y N más"). Serializa el envelope de forma compacta (no el JSON crudo gigante).
- **max_tokens** de salida acotado (ej. ~700). **temperature** baja (ej. 0.3).
- **Timeout** propio (ej. 30s). Error/timeout de OpenAI → `source_error` (`"ai: <motivo>"`), sin reintentos agresivos, y el `done` igual se emite.
- **Disclaimer fijo** al final del reporte: "— Análisis automático sobre datos sin verificar; validar antes de actuar."
- Si el escaneo no tuvo findings, igual puede emitir un `ai_report` corto ("sin resultados relevantes") o saltarlo — tú decide, pero no falles.

## Tests (pytest, sin llamadas reales)

- **Mockea el cliente OpenAI** (monkeypatch de la llamada async) — NO hagas red real:
  - Envelope con findings → `analyze` devuelve el texto mockeado y el orquestador emite `progress(ai)`, `ai_report` (una vez) y luego `done`.
  - Falta `OPENAI_API_KEY` → `source_error` "ai: sin credencial…", sin `ai_report`, con `done`.
  - `AI_ENABLED=false` → ni `ai_report` ni `source_error` de IA.
  - Error simulado de OpenAI → `source_error` "ai: …" + `done`.
  - Truncado: envelope con muchos findings → verifica que se recorta antes de mandar.
- `ruff` limpio.

## Criterios de aceptación

1. Cualquier escaneo (ej. `osint user <x>`) termina con `progress(ai)` → `ai_report` (markdown) → `done`.
2. Sin `OPENAI_API_KEY` → `source_error` claro y `done`, sin `ai_report`, sin crash.
3. `AI_ENABLED=false` desactiva la IA limpiamente.
4. Error de OpenAI aislado (no tumba el escaneo).
5. Presupuesto de findings/tokens aplicado. Tests verdes (OpenAI mockeado) + `ruff` + README (config `OPENAI_API_KEY`/`OPENAI_MODEL`/`AI_ENABLED`, nota de costo por escaneo y disclaimer).

## NO hagas

- No cambies el protocolo de eventos ni el envelope. No emitas múltiples `ai_report`. No hagas llamadas reales a OpenAI en los tests. No añadas nuevas categorías.

Cuando termines: salida real de `curl -N` de un escaneo mostrando el `ai_report` (con una key de prueba o el `source_error` si no hay key), y resultados de `pytest`/`ruff`.
